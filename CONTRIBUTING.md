# Contributing to FPS Prototype 1

Thanks for helping out. Keep each change focused so reviews stay easy.

## Workflow

1. Fork the repo (or pull latest `main` if you already have access).
2. Create a branch from `main` using the naming scheme below.
3. Make your change, commit with a clear message, and push.
4. Open a Pull Request against `Jatin2705/FPS_Prototype1` `main`.

## Branch Naming

Use a short prefix that matches the kind of work:

| Prefix | Use for |
| --- | --- |
| `feature/` | New gameplay or systems |
| `fix/` | Bug fixes |
| `docs/` | README / CONTRIBUTING / comments |
| `chore/` | Tooling, gitignore, cleanup |

Examples: `feature/reload-animation`, `fix/spawn-point-null`, `docs/update-readme`

## Before You Submit

Before opening a Pull Request, make sure:

- Your project builds without errors.
- You've tested your changes.
- Your branch is up to date with `main`.
- You haven't committed unnecessary files (Library, Temp, Logs, builds).

## Pull Request Checklist

- [ ] My code follows the project structure.
- [ ] I tested my changes.
- [ ] I updated documentation if needed.
- [ ] My commit messages are clear.
- [ ] My Pull Request focuses on one feature or fix.

## Good Commit Message Examples

```
Add player jump animation
Fix enemy patrol bug
Update README installation steps
Refactor weapon manager
```

## Things to Avoid

- Mixing multiple features in one PR
- Renaming unrelated files
- Committing generated Unity files
- Making unnecessary formatting changes

## Need Help?

If you're stuck or unsure how to proceed, create an Issue or ask in the group chat before starting work.
